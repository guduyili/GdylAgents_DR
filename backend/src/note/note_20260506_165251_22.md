# 任务 2: 产品格局

请将本轮新增信息补充到任务概览中：

一、2026 年智能体产品格局的新增判断
1. 市场已由“单一框架竞速”演变为“三层竞争”：底层是开源通用编排框架（LangGraph、CrewAI、AG2/AutoGen、Pydantic AI、LlamaIndex、Haystack 等），中层是厂商原生 SDK/平台（OpenAI Agents SDK、Claude Agent SDK、Google ADK、Microsoft Agent Framework / Semantic Kernel），上层是面向业务人员的可视化/云托管产品（如 Dify 及各云厂商托管式 Agent Builder）。这意味着竞争焦点从“谁能做 agent”转向“谁能以最低治理成本把 agent 送进生产”。
2. 开源与闭源生态不是简单替代关系，而是“框架层开放、运行层收敛”的混合模式：企业常以开源框架保持模型与基础设施可迁移性，再接入云厂商的托管 observability、安全、连接器与部署能力。开放性与企业级能力之间的张力，是 2026 年选型的核心矛盾。

二、主要厂商/平台能力边界补充
1. LangGraph 已形成“生产级状态机/图编排”心智。多来源均把其定位为高控制、高审计、高可靠的默认方案：super-apps.ai 提到其 GitHub stars 达 24.8k，并已在 Uber、Cisco 等公司验证规模化；Firecrawl 文章则给出其月下载量 34.5M、企业采用领先。其能力边界在于：适合复杂、长链路、需 human-in-the-loop、重错误恢复的工作流；但学习曲线较高，通常需 4–8 周才能达到生产就绪。
2. CrewAI 稳定占据“最快原型/角色协作”生态位。其优势是以角色分工映射真实业务团队结构，2–4 小时可做出多 agent 原型、2–4 周可完成较简单生产化；但 observability 与复杂状态管理能力偏弱，流程一旦高度分支化、强一致或需严格审计，往往需要额外工程补强。
3. AutoGen 生态已经分化为 Microsoft 官方重写线与社区延续线。Alice Labs 指出 2025 年出现 AutoGen / AG2 split：Microsoft 维护 v0.4+ 重写版，社区沿用 v0.2 脉络发展 AG2。其能力边界是：更适合对话式协同、研究、数据科学、多 agent 推理；若用于严谨流程自动化，通常需要补充结构化控制层。
4. Microsoft 方向正从“AutoGen + Semantic Kernel”走向更统一的企业平台叙事。Uvik 将 Microsoft Agent Framework 视为 2026 生产领导者之一，适配 .NET / Azure 企业、强调治理与企业支持；Alice Labs 仍把 Semantic Kernel 视为企业栈代表。可推断微软生态的核心边界是：最强在 Azure/.NET 一体化、身份与监控体系集成，但代价是更高的平台锁定倾向。
5. 模型厂商原生 SDK 崛起，形成闭源/半闭源强势层：Claude Agent SDK 被 Alice Labs 视为 2025 末到 2026 增长最快的 Anthropic-native 框架；OpenAI Agents SDK、Google ADK 也进入主流比较名单。它们的边界并非“能力一定更强”，而是“在本家模型、工具协议、托管环境中摩擦最低”，适合模型亲和度强、愿意换取更快交付的团队。
6. LlamaIndex / Haystack 类框架在 2026 不再是通用 orchestration 主角，而是“数据层/检索层优势选手”。super-apps.ai 指出 LlamaIndex 提供 200+ 数据连接器，适合法律研究、金融分析等知识密集型场景。其边界是：当问题本质是私有知识访问、索引与检索优化时优势明显；若目标是复杂 agent 控制流，往往需要与其他 orchestration 层配合。
7. Pydantic AI、Mastra、Agno、mcp-agent 等代表了 2026 年第二梯队创新力量：它们不一定在总体采用度上领先，但分别在类型安全、全栈开发体验、协议集成与可组合性上切入。说明市场已从“大而全通用框架”转向“围绕工程痛点做差异化”的细分竞争。

三、开源与闭源生态分层补充
1. 开源第一梯队：LangGraph、CrewAI、AG2/AutoGen、LlamaIndex、Haystack、Pydantic AI。特点是模型中立、部署灵活、社区驱动、适合自建平台团队。
2. 厂商原生/闭源或半闭源第一梯队：OpenAI Agents SDK、Claude Agent SDK、Google ADK、Microsoft Agent Framework。特点是与各自模型、云服务、权限体系、托管工具链深度耦合，适合已有生态投入较深的企业。
3. 可视化/产品化平台层：Dify 等低代码或托管式产品，以及云厂商的 Agent Builder/Studio 类产品。Firecrawl 文中提到 Dify 在 GitHub stars 上领先（129.8k），说明“平台型产品”在开发者关注度上极强。此层竞争的是连接器、界面、部署与协作，而非底层编排抽象本身。
4. 协议层正在成为新分水岭。Uvik 明确指出 MCP 支持在 2026 已接近“table stakes”；这意味着未来平台竞争不只看 SDK，而要看谁能围绕 MCP、工具网关、审计与身份机制构建生态护城河。协议兼容能力正在替代部分框架 API 成为新的锁定点。

四、代表性产品与工程实践补充
1. 企业若追求高确定性生产流程，最佳实践逐渐收敛为：LangGraph/类似图编排 + 独立 observability（LangSmith/Langfuse/Arize 等）+ guardrails/evals + 自建工具网关。Alice Labs 明确提醒：很多项目卡在 demo 之后，不是框架不行，而是缺 observability、guardrails、evaluation harness 和 deployment story。
2. 若业务目标是“尽快验证 ROI”，CrewAI、Dify、OpenAI Agents SDK 往往更快出结果；但随着任务链加长、审核要求增加、失败恢复复杂化，团队常回迁到更显式的状态机/图工作流架构。这反映了从“易上手”到“可运维”的典型架构迁移路径。
3. 选型标准正在从 GitHub star 转向生产指标。Uvik 提出更实用的五维判断：Cost、Latency、Efficacy、Assurance、Reliability；其核心观点是同一模型在不同框架上，最终任务成功率与总拥有成本可能显著不同。说明 2026 的竞争关键不再是功能表，而是生产表现与治理质量。

五、可直接沉淀到任务结论的竞争格局摘要
1. 2026 年不存在统一赢家，产品格局呈现“按约束条件分工”的稳定分层：控制与合规选 LangGraph，速度与多 agent 协作选 CrewAI，对话式研究选 AutoGen/AG2，Azure 企业选 Microsoft 体系，Anthropic / OpenAI / Google 深度用户分别偏向 Claude Agent SDK / OpenAI Agents SDK / Google ADK，知识密集型场景偏向 LlamaIndex / Haystack。
2. 闭源平台并未消灭开源框架，反而把开源推向“中立编排层”，把自身优势放在“托管运行时、连接器、安全、观测、企业支持”上。未来竞争不是 open-source vs closed-source 的二选一，而是谁能控制 agent 的生产入口与运维面板。
3. 从历史演变看，2024 年的 agent 更像 prompt chaining；2025 年开始向 graph/workflow、durable execution、human-in-the-loop 收敛；到 2026 年，协议互通（MCP）、多层产品化和企业治理成为新的主战场。
