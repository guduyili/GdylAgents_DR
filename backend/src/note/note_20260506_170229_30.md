# 任务 1: 技术范式

任务概览
- 主题：2026智能体agent调研
- 子任务：技术范式
- 目标：梳理2026年智能体的核心技术路线与系统架构，明确 LLM Agent、规划、记忆、工具调用、多智能体、Computer Use 等概念边界与演进关系。

已补充的关键发现
1. 概念边界正在从“LLM + Prompt”转向“LLM 作为策略核心 + 外部系统组件”的模块化范式。
   - 2026年的主流定义中，AI Agent 已不再等同于聊天模型，而是由 policy/LLM core、memory、planner、tool router、critic/verification、world model/环境状态 等部件构成的执行闭环。
   - 价值：这一定义澄清了 LLM Agent 与传统问答/聊天机器人的边界，也解释了为什么“能调用工具、可维护状态、可验证结果”才是工程上真正的 agent 化。
   - 依据：arXiv 综述《AI Agent Systems: Architectures, Applications, and Evaluation》明确给出统一 taxonomy，并强调 agent 是把自然语言意图翻译成 procedures 的控制器，而非仅文本生成器。

2. 规划（planning）正从显式“长链推理”演进为分层控制：反应式执行、层级规划、验证回路并存。
   - 当前技术路线并非单一路径：一类是 reactive policy，边观察边行动；一类是 hierarchical / multi-step planner，先拆解后执行；还有 increasingly common 的 critic/self-reflection/verification 回路，用于在长任务中纠错。
   - 价值：这说明“规划”不是单独一个模块，而是 agent 控制栈中的不同时间尺度决策机制。对于复杂任务，真正有效的系统架构通常不是只靠 CoT，而是“计划—执行—检查—重规划”的闭环。
   - 工程含义：高自主任务更依赖约束感知决策、失败恢复、trace-based 调试；否则长任务会因误差累积而崩溃。
   - 依据：该综述明确提出 deliberation/reasoning、planning/control、tool/environment interaction 三大层，并强调长时程任务中的非确定性、信用分配和重试成本。

3. 记忆已从“把历史塞进上下文”升级为一等架构组件，且 selective memory 正在取代 full-context 成为生产主流。
   - 2023年前后，开发者常把 conversation history 直接塞入上下文窗口；到 2026 年，memory 已有独立 benchmark、方法谱系和基础设施生态。
   - LOCOMO 的出现标志着长期会话记忆进入可复现评测阶段。评价维度已不只看准确率，还同时看 token、latency、answer correctness。
   - 数据对比：Full-context 在 LOCOMO 上 LLM Score 72.9%，但中位延迟 9.87s、p95 17.12s、约 26,000 tokens；Mem0 为 66.9%、0.71s、约 1,800 tokens；Mem0g 为 68.4%、1.09s、约 1,800 tokens。即 selective memory 以约 5–6 个点精度代价，换取约 90% token 节省与 91% p95 延迟下降。
   - 价值：这说明记忆系统的核心问题不再是“能不能记住”，而是“如何在可控成本下检索最相关状态”。它也重塑了 LLM Agent 与 RAG 的边界：RAG 偏外部知识 grounding，agent memory 偏持久化用户/任务/交互状态。
   - 进一步演进：多智能体场景中，记忆还需区分个人记忆、共享团队记忆、层级记忆与任务记忆 scope，而不是单一向量库。

4. 工具调用（tool use）已从能力增强插件演进为治理与可靠性的核心接口层；Computer Use 是其中最“具身化”的子范式。
   - 工具调用不只是“会不会用 API”，而是通过 schema、router、权限边界和可审计接口，将语言模型与检索、代码执行、企业系统、浏览器和多模态感知连接起来。
   - MRKL-style 的 modular routing 被强调，是因为它把语言理解与专业工具分离，使接口更可审计、可治理、可替换。
   - Computer Use 应被视为 tool use 的极端形式：不是直接调用抽象 API，而是通过视觉/GUI/action loop 直接操作浏览器、桌面和应用。它扩展了 agent 的适用面，但显著提高了环境脆弱性、步骤长度与失败恢复难度。
   - 依据与数据：computer-use benchmark 在 2025–2026 快速兴起，CUB 这类高难基准最高分仍仅约 10.4%，说明“会用电脑”比“会答题”难得多；一些 50-step web task 上 SoTA 也只在三成量级，反映 GUI 智能体距离稳定生产仍有差距。
   - 价值：这有助于澄清概念边界——tool use 是总类，RAG/API/code interpreter/browser/desktop control 都是其子类；Computer Use 不是独立于 agent 的东西，而是环境交互能力最重的一支技术路线。

5. 多智能体不是“多开几个 prompt”，而是组织结构问题；其收益取决于通信拓扑、角色分工与记忆/权限分层。
   - 2026年多智能体系统的关键不在 agent 数量，而在 orchestration pattern：single-agent vs multi-agent、centralized vs decentralized coordination，以及任务委派机制是否清晰。
   - 最新公开资料显示，多智能体协作可显著提升复杂任务表现，但前提是 targeted communication 和定义良好的 topology；广播式通信往往失败。
   - 价值：这说明多智能体的实质更接近“分布式系统设计”而非提示词堆叠。真正难点在于：谁规划、谁执行、谁持有共享记忆、谁有工具权限、谁来做 critic 和 final approval。
   - 工程建议：在企业实践里，更可行的路线通常是“单主控 agent + 专家子 agent + 分层记忆 + 明确 delegation token / capability boundary”，而不是完全自治的去中心化群体。

补充判断
- 2026 年 agent 技术范式的主轴，正在从“更强模型”转向“更强系统”：当基础模型差距收敛后，规划、记忆、工具路由、验证和编排成为性能差异的主要来源。
- 评测也从静态知识 benchmark 转向面向真实工作流的端到端 benchmark，但 benchmark 与生产表现仍有显著鸿沟，尤其体现在长时程任务、企业约束、环境变化和安全治理上。
- 安全与透明度成为系统架构的一部分，而非事后补丁。AI Agent Index 显示，多数部署系统缺乏公开的 agent-specific safety evaluation，说明行业在能力增长之外，治理成熟度仍明显滞后。
