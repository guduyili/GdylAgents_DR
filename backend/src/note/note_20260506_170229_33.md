# 任务 4: 评测安全

请将本轮新增信息补充到任务概览中

【本轮新增要点建议补充】
1. 评测对象已从“模型输出”扩展到“智能体运行时”：需要同时覆盖任务完成率、工具调用正确性、工作流稳定性、成本/时延预算、权限边界、安全攻击面与合规审计证据。可参考 Quantiphi 对 agent evaluation 的定义：评估不仅看正确性，还要看 consistency、explainability、safety across multi-step processes。
2. 2026 年企业级趋势明确指向“运行时治理（runtime governance）+ 持续评测（continuous evaluation）”。Fei Gao 提到 enterprise readiness 需要 evaluation in production、cost/latency budgets、drift monitoring、context relevance；Quantiphi 引述 Gartner 观点强调 runtime inspection and enforcement，以实时发现性能退化、数据漂移与未授权行为。
3. 关键失效模式应纳入统一评测框架：工具误用、无限循环、上下文丢失、幻觉、权限越权、资源耗尽、集成失败、提示注入、跨智能体级联错误、对工具结果过度信任。建议按“单步错误—多步放大—跨系统外溢”三级建模风险。
4. 安全评测重点正在从 jailbreak 扩展到 tool-using agent 风险：间接提示注入、数据泄露、凭据滥用、非预期动作、MCP/工具协议边界安全。Fei Gao 和 AccuKnox 均强调 allowlist、sandbox、强认证、prompt firewall、runtime protection、MCP security 等控制。
5. 工具生态呈分层化：
   - 观测/追踪/eval：LangSmith、Arize Phoenix、Braintrust、Galileo；
   - 自动评测/回归：DeepEval、Patronus；
   - 红队/安全防护：Lakera Guard、Giskard、promptfoo；
   - QA/合规证据：SureWire。
   说明企业实践不应依赖单一工具，而应采用“trace + eval + red team + policy evidence”组合栈。
6. 合规治理基线逐渐清晰：NIST AI RMF、ISO/IEC 42001、EU AI Act 被频繁提及，意味着评测框架不能只输出分数，还要输出可审计控制项、风险分级、审批流和留痕证据。
7. 建议在任务概览中补充一个六维评测框架：
   - 效果：任务成功率、目标达成率、人工接管率；
   - 成本：单任务 token、工具/API 成本、失败重试成本；
   - 时延：首响应、端到端完成时长、关键步骤 P95；
   - 可靠性：循环率、回退率、重试成功率、跨版本回归；
   - 安全：注入成功率、越权动作率、敏感数据泄露率；
   - 合规：审计日志完整率、策略命中率、人工审批覆盖率。
8. 建议将评测流程设计为四层闭环：离线基准测试 → 场景化仿真 → 预生产红队/对抗测试 → 生产运行时监控与抽样复评。其价值在于解决“benchmarks don’t transfer”的问题，避免实验室高分但生产失效。
9. 从工程实施角度，评测体系要与 CI/CD 和 policy enforcement 联动：把 prompt/tool/agent graph 变更纳入回归测试，把生产失败轨迹自动沉淀为新的 eval case（Braintrust 的思路），形成 failure-to-test 的自进化机制。
10. 初步结论：2026 智能体评测安全的核心不是做一个更大的 benchmark，而是建立“面向运行时、面向工具调用、面向审计合规、面向持续对抗”的治理框架。
