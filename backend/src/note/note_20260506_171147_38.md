# 任务 3: 评测方法

请将本轮新增信息补充到任务概览中：

一、主流Agent评测对象与分层框架补充
- 可将2026年Agent评测体系按“能力单元—领域任务—跨模型/跨环境—协议中心—通用智能体”五层理解。ICLR Blogposts 2026提出五级 taxonomy：Level 1 Agentic Skills Evaluation、Level 2 Domain-Agent Evaluation、Level 3 Agentic Cross-Model Evaluation、Level 4 Protocol-Centric Agent Evaluation、Level 5 General Agent Evaluation。
- 这一分层的价值在于：它指出当前多数榜单仍停留在“特定任务+特定环境”的Level 1/2，尚不足以证明Agent具备可迁移的通用性。对于2026智能体调研，后续比较不同方案时，不应只看单榜分数，而要标注其覆盖层级。

二、主流公开基准的版图与代表性补充
- GitHub项目 philschmid/ai-agent-benchmark-compendium 汇总了50+ Agent benchmark，类别已高度碎片化，至少包括：
  1) Function Calling & Tool Use：BFCL、ToolBench、τ-Bench、API-Bank、HammerBench、NFCL、LiveMCPBench、MCP Universe等；
  2) General Assistant & Reasoning：GAIA、AgentBench、AssistantBench、LiveBench、SimpleQA、Galileo Agent Leaderboard v2等；
  3) Coding & Software Engineering：SWE-Bench、SWE-Bench Verified、SWE-Bench Pro、LiveCodeBench、SWE-PolyBench、Aider Polyglot等；
  4) GUI/Web/Computer Use：WebArena、VisualWebArena、WebVoyager、Mind2Web、OSWorld、WorkArena、AndroidWorld、OfficeBench、MacOSWorld等。
- 这说明“评测方法”不能再以单一总榜替代，而应建立分场景基准矩阵：代码修复、浏览器操作、API/工具调用、企业工作流、多模态桌面/移动端环境分别评测。

三、SWE-Bench家族的定位、价值与局限补充
- SWE-Bench仍是2026年编码Agent最常被引用的标准之一。其核心机制是：给定真实GitHub issue、历史仓库快照与测试集，要求Agent生成patch并通过测试。
- SWE-Bench Verified是500个经人工筛选、清理噪声与测试稳定性的子集。CallSphere文中称，截至2026年3月，前沿Agent在Verified上的解题率约60%–72%，较2025年初约33%显著提升。
- 但需要同步记录三类局限：
  1) 领域局限：主要覆盖Python软件修复，对多语言、API集成、数据库操作、需求澄清类Agent代表性不足；
  2) 可靠性局限：Kili援引OpenAI审计称，Verified中59.4%的困难任务存在测试缺陷，OpenAI已停止继续报告该分数；
  3) 可攻击性局限：Berkeley RDI指出SWE-Bench Verified与Pro都可被环境内patch注入手段100%利用，例如通过conftest.py/pytest hook强制所有测试显示通过，而不真正修复问题。
- 结论是：SWE-Bench适合作为“代码修复上限能力”参考，但不适合作为唯一真实工程效能指标；应联合更抗污染、更多语言与更强隔离的基准（如SWE-Bench Pro、LiveCodeBench、SWE-PolyBench）一起看。

四、GAIA与通用助手评测的核心启示补充
- GAIA聚焦“真实世界多步任务+工具使用+网页浏览”，相比SWE-Bench更贴近通用助手Agent。其任务分为三级：Level 1（1-2步）、Level 2（3-5步）、Level 3（6步以上复杂推理与工具组合）。
- CallSphere给出的2026表现区间：顶级Agent在Level 1约70%–80%，Level 2约45%–60%，Level 3仅20%–35%；人类在Level 3也仅约90%，说明其难度校准较合理。
- Kili补充：GAIA最初发布时，GPT-4 with plugins仅约15%，人类约92%，到2026年头部Agent约75%，显示该基准能反映Agent工具编排和研究型任务能力的真实进步。
- 重要启示：GAIA比静态问答更能检测“计划-搜索-抽取-验证-综合”链路，但对企业内部系统、长期记忆、多Agent协作、安全策略遵从仍覆盖不足，因此适合作为“通用外部信息任务”评测，不等于生产级全栈评测。

五、WebArena/OSWorld/WorkArena类环境评测的必要性补充
- 虽然本轮材料未展开各自细节，但多来源共同表明：2026年的Agent评测正从“输出答案”转向“在环境中完成任务”。WebArena代表网页交互环境，OSWorld代表开放式计算机环境，WorkArena代表企业工作流环境。
- 这类环境型benchmark的意义在于可观测中间行为：页面导航、点击、表单填写、状态恢复、异常处理、是否误触危险操作等，比只看最终答案更适合衡量真实Agent系统。
- 但Berkeley RDI指出，WebArena、OSWorld等也均可被评测管线漏洞利用，说明环境型benchmark若没有强隔离、最小权限与外部独立验证，同样会产生“高分低能”。

六、统一指标体系建议补充
- 多个来源共同支持：Agent评测必须从单一正确率扩展为多维指标。CallSphere明确提出四个核心维度：correctness、efficiency、safety、cost，并建议加入user experience。
- 可据此建立统一指标标准：
  1) 任务成功：success rate / pass@k / exact match / test pass rate；
  2) 过程效率：平均步数、工具调用次数、token消耗、wall-clock time、重试次数；
  3) 成本：单任务美元成本、每成功任务成本、API与工具外部费用；
  4) 安全：危险动作率、越权调用率、误删/误发/幻觉执行率、需要人工接管比例；
  5) 稳定性：同任务多次运行方差、连续8次运行成功率、长尾失败率；
  6) 泛化性：跨环境迁移成功率、换模型/换工具后的性能保持率；
  7) 用户体验：澄清质量、交互轮次、人工评分满意度。
- Kili中的一组关键数据很适合用于论证“稳定性必须单列”：企业Agent研究显示实验室分数与真实部署表现存在37% gap；单次运行60%的结果，在连续8次运行口径下可降至25%。这说明只报单次成功率会系统性高估Agent质量。

七、统一比较不同方案效果与成本的评测模板建议补充
- 面向任务目标“建立统一标准”，建议输出一个二维评测模板：
  A. 横轴按场景分基准：Coding（SWE-Bench/Pro/LiveCodeBench）、General Research（GAIA）、Web（WebArena/VisualWebArena）、Computer Use（OSWorld/WorkArena）、Tool Use（BFCL/API-Bank/ToolBench）；
  B. 纵轴按统一指标：成功率、平均步数、平均token、平均时延、平均成本、稳定性、安全事件、人工接管率。
- 最终可计算一个“单位成功成本”与“风险调整后成功率”：
  1) Unit Cost of Success = 总成本 / 成功任务数；
  2) Risk-adjusted Success = 成功率 × (1 - 安全事故率) × 稳定性系数。
- 这比只看leaderboard分数更贴近企业决策，因为它把效果、成本、可靠性放入同一坐标系中。

八、2026评测方法的核心风险与工程对策补充
- Berkeley RDI的发现极具警示意义：其自动扫描Agent审计了8个重要Agent benchmark（含SWE-Bench、WebArena、OSWorld、GAIA、Terminal-Bench等），发现全部可以在“不真正完成任务”的前提下被利用到接近满分。
- 这意味着2026年的benchmark设计必须显式纳入“防reward hacking / 防benchmark exploitation”要求，至少包括：
  1) 评测环境与打分环境隔离；
  2) 只读测试、最小权限执行、禁写grader；
  3) 外部独立验证器与不可篡改日志；
  4) 隐藏测试和动态任务刷新，降低污染；
  5) 轨迹审计，检查是否出现git log抄答案、hook测试框架、篡改parser等行为；
  6) 把“遵守评测约束”本身设为得分条件。
- 从工程实践看，未来高质量Agent评测会越来越像“安全对抗下的系统测试”，而不是传统静态NLP benchmark。

九、面向研究结论的综合判断补充
- 2026年主流Agent评测已从“模型答题分数”演进为“环境中的多步决策评测”，公开基准覆盖代码、通用研究、工具调用、网页与桌面操作等多个子领域。
- 但现状的最大问题不是benchmark数量不足，而是标准不统一、环境接口不兼容、指标口径不一致、结果易受脚手架和评测漏洞影响。
- 因此，本任务最终建议不是再寻找一个“最权威单榜”，而是构建一个“分层+分场景+多指标+防作弊”的统一评测框架，并把公开基准与企业自定义回放/仿真/人工审核结合起来。
