# 任务 5: 安全治理

请将本轮新增信息补充到任务概览中：

1. 风险判断应从“模型输出安全”升级为“代理执行安全”。多源资料一致指出，Agent的核心风险不再只是生成有害文本，而是能跨系统调用API、读写企业数据、触发支付/审批/基础设施操作，因此安全边界从内容过滤转向权限、身份、工作流和可审计性。可在任务概览中补充：Agent安全问题本质上是“语言层漏洞 + 机器身份滥用 + 自动化执行放大”的复合风险。

2. Prompt Injection 是当前Agent治理的首要风险，而且不存在单一模型层修复。Atlan指出，LLM无法在架构上把“指令”和“数据”做语法级彻底分离，攻击者可通过用户输入、RAG文档、网页内容、邮件/PDF、甚至长期记忆库注入恶意指令，诱导泄密、越权执行或绕过策略。可补充其治理含义：不能把防护希望寄托于单一system prompt，而应建立输入净化、上下文分区、工具调用前策略检查、输出审查和高风险动作二次确认的纵深防御。

3. 数据/记忆投毒是Agent时代比传统应用更隐蔽的供应链问题。OWASP相关材料援引研究称，仅约250份恶意文档即可在大模型生态中形成后门效应；Baker Botts材料也强调记忆注入、RAG污染和敏感信息泄漏具有高成功率。建议在任务概览对应“风险来源”段落加入：外部知识库、内部文档库、长期记忆、插件返回值和消息平台都应被视作不可信输入源，需要文档签名、来源分级、检索白名单、记忆TTL、敏感字段脱敏与隔离检索。

4. Human-in-the-loop 不能被理解为“有人看着就行”，而应被设计成分级授权机制。Strata明确区分 HITL（执行前批准）与 HOTL（执行后监控/可干预）：高风险动作如付款、合同提交、访问敏感数据、变更权限必须采用HITL；中低风险场景可采用HOTL。其价值在于把治理从抽象原则落到决策门禁。建议补充一个实践框架：按动作风险等级、资金阈值、数据敏感度、跨系统影响范围设审批门槛，并要求审批人具备上下文、介入权与可追责理由。

5. 合规与责任正在从“可选最佳实践”变成“默认问责”。Baker Botts指出，到2026年底非人类/代理身份预计将超过450亿，且仅约10%的组织拥有相关治理策略；同时加州AB 316已明确不得以AI自主运作为责任抗辩。MoogleLabs材料提到欧盟AI法案最高罚款可达3500万欧元或全球营业额7%。可在任务概览中补充：企业部署Agent时应像授予员工签字权一样进行治理，至少覆盖五层控制——Scope（能力边界）、Identity（短期凭证/证书/最小权限）、Monitoring（全链路日志和异常检测）、Override（kill switch与人工接管）、Accountability（内部Owner与供应商责任划分）。
