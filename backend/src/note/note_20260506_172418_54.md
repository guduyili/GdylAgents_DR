# 任务 4: 评测方法

请将本轮新增信息补充到任务概览中：

## 任务总结

1. **Agent 评测正在从“单点正确率”转向“多维系统评估”，轨迹质量与安全性成为核心维度。** 现有材料一致强调，Agent 与传统 LLM/ML benchmark 的根本差异在于：不仅要看最终是否完成任务，还要看执行路径是否合理、安全、可恢复、成本可控。可采用四层指标体系：任务成功率（pass rate / pass@k）、轨迹质量（step efficiency、tool accuracy、recovery rate）、效率（token cost、latency、tool calls）、安全与可靠性（hallucination rate、guardrail violation、graceful failure）。其价值在于防止“结果正确但过程危险”的伪优，例如通过删除文件、泄漏数据或反复试错得到正确答案的 Agent，不应与安全高效完成任务的 Agent 同分。这意味着 2026 年 Agent 评测设计应默认输出“指标面”而非单一总分。

2. **评测框架本身已成为瓶颈：环境接口、协议和指标命名不统一，阻碍跨 Agent / 跨环境可比性。** ICLR 2026 blogpost 提出五级评测谱系（技能级、领域级、跨模型级、协议中心级、通用 Agent 级），指出当前 benchmark 之间不仅环境约束不兼容，连基础指标的名称、聚合方式、成本统计口径都不一致。Table 4 明确提到不同 benchmark 在 success/cost reporting 上存在不兼容格式；Table 5 则显示 MCP 支持不均衡，常见实现仅支持 tool calling，不支持 resources/prompts，导致高集成成本。其价值在于提示研究与工程团队：若要建立 2026 面向采购/选型的评测方法，必须先定义统一 agent interface、environment interface 与 researcher interface，否则 leaderboard 很难直接横向比较，尤其无法公平比较不同 scaffolding、工具协议和部署形态。

3. **“长时程评测缺口”是当前 Agent Benchmark 最大失真来源：短任务高分不代表生产可用。** Long-horizon 研究指出，模型在短任务上的高通过率会随任务长度显著、且超线性下降：基于 23,392 个 episode 的可靠性研究显示，pass@1 可从 76.3% 下降到 52.1%；软件工程任务中的 Graceful Degradation Score 从 0.90 降至 0.44。文章还给出更强烈信号：在 SWE-Bench Verified 上约 75% 的模型，在需要人类数小时完成的 SWE-Bench Pro / 长时程任务上可能跌至 25% 以下。暴露出的关键失败模式包括：compounding errors（早期小错级联放大）、state drift（目标漂移）、meltdown behavior（循环、幻觉工具输出、自相矛盾）、tool use degradation（长上下文下工具调用质量恶化）、irreversible action risk（不可逆操作带来的系统性风险）。这说明 2026 评测方法必须加入任务长度分桶、连续多轮稳定性测试、多次运行一致性，以及失败后恢复能力评估，否则只能测“demo intelligence”，不能测“production reliability”。

4. **头部基准正在快速分化：SWE-bench、GAIA、WebArena、OSWorld 等各自覆盖不同能力面，必须组合使用。** 从资料可提炼出一个能力覆盖矩阵：SWE-bench / SWE-bench Pro 衡量代码库理解、补丁生成、测试验证；GAIA 衡量多步工具使用、网页浏览与多模态通用助理能力；WebArena 衡量真实网页流程执行；OSWorld 衡量跨操作系统电脑任务；τ-bench 聚焦带政策约束和工具调用的多轮客服场景。其价值在于建立“场景-指标-基准”映射，而非迷信单榜。代表性数据包括：GAIA 发布时 humans 92%，GPT-4 + plugins 15%；WebArena 初始模型成功率 14%，人类 78%；OSWorld 从约 12% 提升到 66.3%，已接近人类 6 个百分点以内；AI Index 2026 指出 agent 在结构化 benchmark 上仍大约每三次失败一次。对于企业或研究团队，正确做法不是问“哪个 benchmark 最好”，而是按照产品目标将 benchmark 组合成 portfolio：编码 Agent 看 SWE-bench Pro + 长时程私有代码任务，通用办公 Agent 看 GAIA + WebArena + OSWorld，客服 Agent 看 τ-bench + 策略合规测试。

5. **2026 年更有价值的比较方法应从“榜单排名”升级为“效果—稳定性—成本—安全”四维决策面板，并引入污染与脚手架控制。** SWE-bench 相关材料显示，Verified 虽仍被广泛引用，但存在训练污染和题目质量问题：例如 Claude Opus 4.5 从 Verified 80.9% 跌到 Pro 45.9%，GPT-5 High 从约 55% 跌到 23.3%；OpenAI 审计还指出 59.4% 的 hardest unsolved Verified tasks 含有 flawed test cases。SWE-bench Pro 通过私有代码库、跨语言任务、统一 scaffolding、250-turn 限制来提高判别力，更接近真实使用。结合 Stanford HAI AI Index 2026 的结论——前沿模型能力差距缩小、竞争压力转向 cost、reliability 和 real-world usefulness——说明未来评测报告应至少包含：成功率/通过率、方差与置信区间、平均与尾延迟（P50/P95 latency）、单任务 token/API 成本、单位成本成功率、违规率/幻觉率、跨 5~8 次重复运行的一致性、在私有/未见环境中的泛化表现。工程上建议采用沙箱（Docker/VM）、固定种子与温度、n≥5 重复运行、轨迹日志、LLM-as-judge + rubric + 参考答案的混合判定机制，并单独报告 judge bias 风险。
