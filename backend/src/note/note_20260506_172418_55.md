# 任务 5: 风险治理

请将本轮新增信息补充到任务概览中：

1. 风险画像需从“模型输出风险”升级为“行动型风险”治理。结合 NIST 2026 AI Agent Standards Initiative 与联邦/国防侧咨询，Agent 的核心风险已从内容不当扩展为工具调用、跨系统执行、持久记忆、代理委托与多步规划失控。其治理重点不再只是静态模型评测，而是覆盖模型层、Agent 层、人类监督层三层控制。价值在于：这解释了为什么传统 GenAI 审核机制不足以覆盖 Agent，尤其是在金融、医疗、政务、国防等高影响场景。

2. 实证研究显示 Agent 特有攻击成功率显著高于传统基线，红队化应成为常态控制而非上线前一次性测试。CSA/Labs 对 NIST 相关研究的整理指出，面向 Agent 行为模式设计的新型攻击将任务劫持成功率从 11% 提升到 81%。NIST AI 100-2 更新也首次将间接提示注入、记忆污染、工具供应链攻击纳入对自主 Agent 的对抗性分类。价值在于：企业若只沿用传统 LLM jailbreak/毒性测试，极可能系统性低估真实攻击面；红队、持续评测、回归测试应嵌入 SDLC 与运行期。

3. 权限控制正在从“用户登录鉴权”演进为“Agent 身份 + 委托授权 + 最小能力边界”的组合架构。NCCoE 2026 概念方案已提出以 OAuth 2.0、SPIFFE/SPIRE、MCP 为核心构建 Agent identity and authorization。对 Agent 来说，真正的风险不是是否接入工具，而是能否证明“谁授权该 Agent 在什么范围内、何时、以何种身份调用何种工具”。价值在于：这是解决越权执行、横向移动、工具滥用、伪装人类操作的关键工程抓手。实践上应采用短时凭证、细粒度作用域、每次工具调用重做策略判定、分离读写权限与高危动作审批。

4. 可审计性正在成为治理落地的分水岭，‘可验证证据’比‘制度文本’更重要。Digital Applied 的治理框架强调，真正有效的控制必须回答三个问题：运行在代码/基础设施的哪里、产出什么可供外部审查的证据、失败时谁被告警。其给出的工程化示例包括：每次工具调用输出结构化追踪，至少含 user ID、tool name、input hash、authorization decision，并在 append-only 存储中保留 90 天。价值在于：这将 EU AI Act、NIST AI RMF、SOC2 等抽象要求转译为工程控制，避免“纸面合规”“清单表演”“事后补证”。

5. 合规框架正在收敛为‘EU AI Act 负责义务分层，NIST AI RMF 负责治理方法，未来 SP 800-53/COSAiS 负责控制细化’的三层体系。EU AI Act 对高风险系统要求风险管理、数据治理、技术文档、记录留存、人类监督、鲁棒性/网络安全等，且高风险义务将在 2026-08-02 广泛生效；NIST AI RMF 虽属自愿，但在美国联邦采购、企业问卷、SOC2 AI readiness 中近乎事实标准；COSAiS 预计将为单 Agent / 多 Agent 提供专门控制覆盖，并可能演化为未来 FedRAMP AI 要求基础。价值在于：企业应尽早建立控制映射矩阵，把政策条文映射到访问控制、日志、沙箱、审批流、红队与变更管理，而不是等客户审计时临时拼接证据。

6. 可行治理框架建议采用‘政策—权限—运行时防护—审计证据—事件响应’闭环，而非单点 Guardrail。具体包括：
   - 政策层：定义 intended purpose、禁止用途、例外审批、人类监督决策矩阵；
   - 权限层：Agent 独立身份、最小权限、分级工具访问、敏感操作双人/人工批准；
   - 运行时层：沙箱执行、Prompt Firewall、数据外发限制、会话/记忆隔离、异常行为检测；
   - 审计层：结构化 trace、不可篡改日志、版本化提示词/工具清单/策略变更记录；
   - 响应层：越权/注入/泄漏事件的 kill switch、回滚、撤销令牌、法务与合规联动。
该闭环的价值在于兼顾安全、隐私、权限控制、审计与合规五大目标，且比单纯依赖模型对齐或输出过滤更贴近 Agent 的真实系统边界。
